Actúa como un ingeniero senior de software, QA automation lead, auditor técnico full-stack y especialista en debugging de producción.

Tu misión es realizar una AUDITORÍA COMPLETA de esta aplicación y después EJECUTAR LAS CORRECCIONES necesarias de forma inmediata, segura y verificable.

## Objetivo principal
Quiero asegurarme de que TODAS las funciones de la app:
1. estén operativas,
2. hagan exactamente lo que prometen,
3. no tengan errores ocultos,
4. estén conectadas correctamente entre frontend, backend, base de datos, storage, APIs, rutas y permisos,
5. y que cada pestaña, página, formulario, botón, acción y flujo crítico sea probado de punta a punta.

## Problema prioritario conocido
Ahora mismo NO funciona correctamente la opción de:
- ver imágenes
- editar imágenes
- subir imágenes

en el módulo o sección donde se encuentra la flota de barcos.

Ese problema debe ser tratado como PRIORIDAD ALTA. Debes investigar la causa raíz y corregirlo completamente.

## Fase 4: Corrección inmediata
Todo error encontrado debe ser:
1. diagnosticado,
2. explicado,
3. corregido,
4. probado nuevamente,
5. y validado con evidencia.

No te limites a reportar. Debes PROCEDER A RESOLVER los problemas detectados.

Antes de cada corrección importante:
- identifica la causa raíz,
- evita romper otras funciones,
- conserva compatibilidad con el resto del sistema,
- y aplica cambios limpios, mantenibles y coherentes con la arquitectura existente.

Si encuentras varias causas relacionadas, resuélvelas de forma integral, no solo superficialmente.

---

## Fase 5: Re-testing y validación final
Después de corregir, vuelve a ejecutar pruebas completas para confirmar que:
- la funcionalidad corregida ya opera correctamente,
- no se introdujeron regresiones,
- todas las páginas y pestañas siguen funcionando,
- y la sección de flota de barcos permite ver, editar y subir imágenes sin errores.

# CRITERIOS DE CALIDAD

## Debes:
- ser exhaustivo, no superficial
- no asumir que algo funciona solo porque compila
- validar comportamiento real
- revisar toda la experiencia del usuario
- priorizar estabilidad, funcionalidad y consistencia
- dejar el sistema funcionando mejor que como estaba
- documentar hallazgos con claridad técnica

## No debes:
- hacer cambios innecesarios
- romper funcionalidades existentes
- omitir pruebas de regresión
- dar por resuelto algo sin comprobarlo
- limitarte a “parece funcionar”

---

# FOCO ESPECIAL: FALLO DE IMÁGENES EN FLOTA DE BARCOS

Investiga específicamente todas estas posibles causas:
- input file mal conectado
- endpoint incorrecto
- error en formData
- nombre de campo incorrecto
- fallo de validación backend
- storage/bucket mal configurado
- URL de imagen mal construida
- problema de permisos de lectura/escritura
- error en actualización de registro
- imagen subida pero no persistida en DB
- imagen persistida pero no renderizada
- fallo de path relativo/absoluto
- problema de CORS
- problema de autenticación
- componente de preview roto
- error en modo edición
- error en recuperación de imágenes existentes

Corrige todo lo necesario hasta que el flujo completo funcione:
1. seleccionar imagen,
2. subir imagen,
3. guardar,
4. recuperar,
5. visualizar,
6. editar si aplica,
7. persistir correctamente tras recarga.

---
