# PROMPT MAESTRO — AUDITORÍA Y REPARACIÓN TOTAL DEL FLUJO:
# SUBIDA DE ESTADO BANCARIO → CLASIFICACIÓN INTELIGENTE → ENVÍO A CONTABILIDAD

Detén cualquier ajuste superficial.

No quiero parches visuales.
No quiero suposiciones.
No quiero que se marque como “completado” un flujo que en la práctica no está funcionando.

Necesito que revises, valides y repares de punta a punta el flujo completo que inicia cuando se sube el estado del banco y continúa con la clasificación inteligente hasta el envío final de gastos o ingresos a contabilidad.

---

# CONTEXTO DEL PROBLEMA

Actualmente existe una falla en el flujo posterior a la subida del estado bancario.

## Flujo esperado
1. se sube el estado del banco,
2. el sistema procesa el archivo,
3. entra en clasificación inteligente,
4. se clasifican movimientos como gastos o ingresos,
5. y luego esos movimientos deben enviarse correctamente a contabilidad.

## Problema actual
Cuando el estado del banco llega a clasificación inteligente y se procede a enviar los gastos o ingresos a contabilidad, **no funciona**.

No asumas que el problema está en un solo punto.
Debes revisar el flujo completo de extremo a extremo.

---

# OBJETIVO PRINCIPAL

Quiero una auditoría técnica total y una reparación funcional completa del flujo para garantizar que:

- el archivo se reciba correctamente,
- se procese correctamente,
- la clasificación inteligente funcione como debe,
- los movimientos queden bien tipificados,
- el envío a contabilidad se ejecute realmente,
- los estados cambien correctamente,
- y todo el proceso quede estable, trazable y operativo.

---

# REGLA CRÍTICA

No quiero que repares solo el síntoma visible.

Quiero que identifiques:
- dónde se rompe realmente el flujo,
- por qué se rompe,
- desde cuándo puede romperse,
- qué parte sí funciona,
- qué parte no,
- qué dependencias están fallando,
- y qué debe corregirse para que el flujo quede confiable.

# FASE 1 — AUDITORÍA COMPLETA DEL FLUJO

Debes revisar el flujo completo desde el inicio hasta el final.

## Auditar paso por paso

### 1. Subida del estado bancario
Validar:
- si el archivo se carga correctamente,
- si se guarda correctamente,
- si se registra en base de datos,
- si el formato se interpreta bien,
- si hay validación de tipo de archivo,
- si hay errores silenciosos,
- si el backend recibe realmente el archivo,
- si el estado inicial del proceso se actualiza correctamente.

### 2. Procesamiento del archivo
Validar:
- parsing del archivo,
- extracción de movimientos,
- estructura de los registros generados,
- campos requeridos,
- importes,
- fechas,
- descripción,
- referencia,
- cuenta bancaria,
- moneda,
- duplicados,
- errores de normalización.

### 3. Clasificación inteligente
Validar:
- si el motor de clasificación se dispara realmente,
- si recibe los datos correctos,
- si clasifica todos los movimientos,
- si clasifica parcialmente,
- si deja estados intermedios inconsistentes,
- si distingue correctamente ingresos vs gastos,
- si existe fallback incorrecto,
- si hay reglas rotas,
- si hay servicios externos fallando,
- si hay timeout,
- si hay errores no visibles en logs.

### 4. Preparación para envío a contabilidad
Validar:
- qué condición habilita el envío,
- si el sistema marca correctamente los movimientos como listos,
- si la validación previa al envío existe y funciona,
- si se están filtrando registros incorrectamente,
- si se están excluyendo movimientos válidos,
- si los campos requeridos por contabilidad están completos,
- si se arma bien el payload de gastos e ingresos.

### 5. Envío a contabilidad
Validar:
- si el botón, acción o trigger realmente ejecuta algo,
- si llama al endpoint correcto,
- si el endpoint existe,
- si el método HTTP es correcto,
- si el payload sale bien formado,
- si el backend recibe la solicitud,
- si la integración con contabilidad responde,
- si hay errores de autenticación,
- si hay errores de validación,
- si hay errores de mapping,
- si hay errores de sincronización,
- si la respuesta se persiste correctamente,
- si el estado final del movimiento cambia correctamente.

### 6. Confirmación y trazabilidad posterior
Validar:
- si queda registro de qué se envió,
- si queda registro de qué no se envió,
- si hay logs por movimiento,
- si se puede reintentar,
- si se duplican envíos,
- si el usuario ve el estado real,
- si el dashboard o módulo refleja correctamente el resultado final.

# FASE 4 — PROHIBICIONES ABSOLUTAS

Queda prohibido:

- marcar movimientos como enviados si no fueron enviados realmente,
- simular éxito sin confirmación real,
- ocultar errores técnicos,
- dejar errores silenciosos,
- usar mocks para aparentar que contabilidad respondió,
- dejar botones activos que no hacen nada,
- dejar estados inconsistentes entre clasificación y contabilidad,
- duplicar envíos,
- perder trazabilidad,
- romper la clasificación inteligente mientras reparas el envío,
- romper la subida del banco mientras corriges lo posterior.

# FASE 5 — REPARACIÓN DEL FLUJO

Una vez detectado el problema, debes corregirlo de forma completa y segura.

## La corrección debe asegurar
- que el archivo se procese bien,
- que la clasificación inteligente deje movimientos utilizables,
- que los gastos e ingresos elegibles puedan enviarse,
- que el envío a contabilidad se ejecute de verdad,
- que el estado se actualice correctamente,
- que el usuario vea el resultado real,
- que haya trazabilidad completa,
- y que no se generen duplicados ni falsos positivos.

## Si el problema está en más de una capa
Debes corregir todas las capas necesarias, no solo la primera que falle.

---

# FASE 6 — NO ROMPER LO QUE YA FUNCIONA

- carga correcta de archivos si ya funciona,
- parsing correcto si ya funciona,
- clasificación correcta si ya funciona,
- registros correctos en base si ya funcionan,
- integraciones sanas ya existentes,
- validaciones correctas,
- trazabilidad útil ya implementada.
