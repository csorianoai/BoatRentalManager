OBJETIVO

CREAR
Una cuenta contable separada, por ejemplo:
- Depósitos de reservas futuras
o

COMPORTAMIENTO

- esos depósitos deben entrar a esa cuenta separada
- no tratarlos inmediatamente como ingreso final realizado
- dejarlos identificados por:
  - cliente
  - barco si aplica
  - fecha
  - monto
  - referencia de booking si existe
  - estado

ESTADOS SUGERIDOS

- aplicado a booking
- reembolsado

OBJETIVO CONTABLE

3. PAGOS DE MARINA Y PAGOS RECURRENTES
==================================================

Cuando ingresemos gastos por pago de marina, necesito evitar duplicidades o conflictos con pagos recurrentes ya creados.

PROBLEMA A RESOLVER
Si ya existe un pago recurrente de marina, no quiero que un gasto manual de marina duplique ese movimiento o choque con la contabilidad.

REGLA DE NEGOCIO
- los pagos fijos o repetitivos de marina deben crearse como pagos recurrentes
- los pagos extraordinarios o no programados de marina sí pueden crearse como gasto manual

IMPLEMENTACIÓN
Agregar una validación para categoría “Marina”:
- si existe un pago recurrente activo similar para ese barco/proveedor/periodo, mostrar advertencia
- sugerir al usuario:
  - usar el pago recurrente existente
  - o confirmar que este gasto es extraordinario/manual

MENSAJE SUGERIDO
“Ya existe un pago recurrente activo de marina para este barco o proveedor. ¿Deseas registrar este gasto como extraordinario o gestionarlo desde pagos recurrentes?”
