Actúa como un senior full-stack engineer con enfoque en performance y simplicidad. No quiero una app nueva. Quiero agregar soporte multiidioma dentro del sistema existente “gestión”, integrado de forma nativa y con el menor consumo posible en Replit.

OBJETIVO
Implementar un sistema de internacionalización (i18n) ligero, escalable y sin dependencias pesadas, que permita cambiar el idioma del portal mediante un selector visual con banderas, manteniendo consistencia con la UI actual.

PRINCIPIOS CLAVE
- No usar librerías externas pesadas (i18next, etc.)
- No usar APIs de traducción en tiempo real
- No duplicar vistas ni componentes
- No romper funcionalidades existentes
- Mantener código simple, modular y extensible
- Optimizar para bajo consumo en Replit
- Preparar base para escalar a más idiomas sin refactor

==================================================
1. IDIOMAS SOPORTADOS (MVP)
==================================================

Implementar estos idiomas iniciales:
- Español (es) [default]
- Inglés (en)
- Francés (fr)
- Italiano (it)
- Portugués (pt)

Diseñar el sistema para agregar nuevos idiomas fácilmente sin cambiar lógica core.

==================================================
2. SELECTOR DE IDIOMA (UI)
==================================================

Agregar un selector visible en el header/topbar del sistema “gestión”.

FORMATO:
🇪🇸 ES | 🇺🇸 EN | 🇫🇷 FR | 🇮🇹 IT | 🇵🇹 PT

REQUISITOS:
- debe integrarse con el diseño actual (no crear UI nueva)
- debe ser liviano (HTML/CSS simple)
- cada opción cambia el idioma inmediatamente
- indicar idioma activo visualmente
- accesible desde cualquier pantalla

==================================================
3. PERSISTENCIA
==================================================

- guardar idioma seleccionado en localStorage (key: app_lang)
- al cargar la app, aplicar automáticamente el idioma guardado
- fallback a “es” si no hay selección

==================================================
4. ARQUITECTURA DE TRADUCCIONES
==================================================

Usar archivos JSON por idioma.

ESTRUCTURA:
- /locales/es.json
- /locales/en.json
- /locales/fr.json
- /locales/it.json
- /locales/pt.json

FORMATO JSON (plano y simple):
{
  "menu.dashboard": "Dashboard",
  "menu.operations": "Operaciones",
  "button.create_task": "Crear tarea",
  "task.status.pending": "Pendiente"
}

REGLAS:
- usar claves consistentes y jerárquicas
- no hardcodear textos en HTML
- evitar nesting profundo para reducir complejidad

==================================================
5. INTEGRACIÓN CON UI
==================================================

Todos los textos visibles deben usar atributos:

data-i18n="clave.traduccion"

Ejemplo:
<button data-i18n="button.create_task"></button>

NO usar innerText fijo en HTML.

==================================================
6. MOTOR DE TRADUCCIÓN (CORE JS)
==================================================

Implementar una función global simple:

changeLanguage(lang)

FUNCIONES REQUERIDAS:

1. loadLanguage(lang)
- carga JSON correspondiente
- guarda en memoria

2. applyTranslations()
- recorre DOM
- busca elementos con data-i18n
- reemplaza texto con traducción

3. changeLanguage(lang)
- guarda en localStorage
- carga idioma
- aplica traducciones

4. initLanguage()
- se ejecuta al cargar app
- detecta idioma guardado
- carga y aplica

OPTIMIZACIÓN:
- cachear traducciones en memoria
- no recargar JSON innecesariamente
- evitar re-render completo
