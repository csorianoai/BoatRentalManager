## PASO 1 — Cache-busting automático para TODOS los assets

No solo fleet-ops.js. Implementa cache-busting para todos los archivos JS y CSS del sistema.

Opciones (elige la más simple para el stack actual):

### Opción A — Timestamp de build (más simple)
En el servidor, en el momento de responder HTML, inyectar un timestamp o hash:

<script src="/assets/js/operations/fleet-ops.js?v={BUILD_TIMESTAMP}"></script>

Donde BUILD_TIMESTAMP se genera al iniciar el servidor o en cada deploy. Todos los archivos JS/CSS comparten el mismo query param.

### Opción B — Hash de contenido (más robusto)
Para cada archivo JS/CSS, calcular un hash MD5 del contenido al iniciar el servidor. Inyectar ese hash como query param:

<script src="/assets/js/operations/fleet-ops.js?h=a3f8b2"></script>

Cambia automáticamente solo cuando el archivo cambia. Más eficiente porque preserva cache de archivos que no cambiaron.

### Opción C — ETags + Cache-Control headers (más profesional)
Configurar el servidor para que envíe:
- ETag basado en hash del archivo
- Cache-Control: no-cache, must-revalidate para HTML
- Cache-Control: public, max-age=31536000, immutable para archivos con query param

Elige la opción A si el stack es simple (Node/Express plain), B si hay build process, C si quieres la solución enterprise.

Decisión sugerida: Opción A por ser más simple. Solo 15 min de implementación. Reporta qué opción elegiste y por qué.
