Actúa como un senior full-stack engineer. No quiero una app separada. Quiero que agregues un nuevo módulo dentro de la herramienta existente llamada “gestión”, como una pestaña adicional del sistema actual.

CONTEXTO DEL SISTEMA ACTUAL
Ya existe una herramienta web llamada “gestión” con dashboard operativo. La nueva funcionalidad debe integrarse dentro de esta plataforma existente, manteniendo coherencia visual, estructura, navegación y estilo UI.

IMPORTANTE
- No crear una aplicación independiente
- No romper la navegación actual
- No cambiar la lógica existente si no es necesario
- Agregar una nueva pestaña o sección dentro de “gestión”
- Respetar el estilo visual actual del dashboard
- Mantener el sistema liviano y optimizado para Replit

OBJETIVO DEL NUEVO MÓDULO
Crear dentro de “gestión” una pestaña nueva para administrar el trabajo operativo del negocio, incluyendo:
- agenda de trabajo
- tareas
- timeline de ejecución
- asignación de responsables
- categorías de tareas
- seguimiento de avance
- relación con otros módulos del sistema
- sincronización con Google Calendar
- sincronización con Google Maps / ubicaciones

NOMBRE DEL NUEVO MÓDULO
Usa “Operaciones”.

4. CONEXIÓN CON OTROS MÓDULOS DE GESTIÓN
==================================================

Este punto es obligatorio.

La pestaña “Operaciones” debe poder conectarse con otros módulos ya existentes o futuros dentro de “gestión”.

A. CONEXIÓN CON GASTOS
Si una tarea corresponde a un gasto, debe permitir:
- marcarla como “relacionada con gasto”
- reenviar o registrar la información relevante en el módulo de Gastos
- crear un registro vinculado o prellenado en la sección de Gastos
- mantener referencia cruzada entre tarea y gasto

Datos mínimos para reenviar:
- título
- descripción
- categoría
- monto si aplica
- fecha
- responsable
- barco o cliente relacionado si aplica
- estado

Ejemplos:
- compra de repuesto
- mantenimiento correctivo
- combustible
- marina / amarre
- limpieza
- insumos operativos

B. CONEXIÓN CON INGRESOS
Si una tarea corresponde a un ingreso, debe permitir:
- marcarla como “relacionada con ingreso”
- reenviar o registrar la información relevante en el módulo de Ingresos
- crear un registro vinculado o prellenado en la sección de Ingresos
- mantener referencia cruzada entre tarea e ingreso

Datos mínimos para reenviar:
- título
- descripción
- monto esperado o real
- fecha
- cliente relacionado
- listing relacionado
- contrato relacionado
- estado

Ejemplos:
- pago pendiente de cliente
- contrato cobrado
- reserva confirmada
- ingreso por charter
- comisión recibida

C. LÓGICA DE ENLACE ENTRE MÓDULOS
Diseñar la estructura para que una tarea pueda:
- existir sola
- vincularse a un gasto
- vincularse a un ingreso
- generar un gasto o ingreso desde un botón o acción rápida
- mostrar el estado del vínculo
- abrir el registro relacionado desde la propia tarea

La arquitectura debe dejar listo un sistema de relaciones internas entre módulos.

5. GOOGLE CALENDAR
==================================================

Agregar sincronización con Google Calendar para que tareas con fecha puedan enviarse y mantenerse vinculadas con el calendario del usuario.

REQUISITOS
- usar integración segura con Google Calendar
- permitir conectar una cuenta de Google
- permitir desconectar la cuenta
- guardar el vínculo del evento creado con la tarea
- permitir crear evento al crear o editar una tarea
- permitir actualizar el evento si cambia la tarea
- permitir cancelar o eliminar el evento si se elimina la tarea o se desactiva la sincronización
- permitir elegir si una tarea se sincroniza o no

DATOS A ENVIAR A GOOGLE CALENDAR
- título de la tarea
- descripción
- fecha inicio
- fecha fin o vencimiento
- responsable si aplica
- ubicación si aplica
- enlace interno a la tarea si existe
- notas relevantes

REGLAS
- implementar de forma liviana
- no sincronizar todo automáticamente sin control
- usar una opción por tarea o por tipo de tarea
- guardar el eventId del calendario en la base de datos
- permitir resincronización si falla
- diseñar la lógica para sincronización incremental y actualización eficiente
