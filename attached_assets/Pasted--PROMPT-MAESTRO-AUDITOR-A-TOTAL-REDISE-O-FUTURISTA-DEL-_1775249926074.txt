# PROMPT MAESTRO — AUDITORÍA TOTAL + REDISEÑO FUTURISTA DEL DASHBOARD SIN ROMPER LO QUE FUNCIONA

Detén cualquier cambio cosmético, parcial o decorativo.

No quiero otro parche.
No quiero otra capa visual encima de un sistema roto.
No quiero un dashboard “bonito” con datos falsos o interacciones vacías.

Quiero una **auditoría funcional completa**, seguida de una **reconstrucción estratégica** y un **rediseño de nivel elite**, con estética futurista, altísima usabilidad, cero ficción operativa y preservación absoluta de todo lo que hoy sí funciona.

---

# OBJETIVO CENTRAL

Necesito que conviertas el dashboard actual en una plataforma:

- **100% conectada a datos reales**
- **100% operativa**
- **visualmente espectacular**
- **futurista pero usable**
- **inteligente en jerarquía visual**
- **rigurosa en métricas**
- **sin romper ninguna funcionalidad válida existente**
- **sin eliminar nada útil antes de auditarlo**
- **sin inventar ningún dato para llenar espacios**

Este trabajo debe ejecutarse en este orden de prioridad:

## Orden obligatorio
1. **Auditar antes de tocar**
2. **Identificar qué sí funciona y protegerlo**
3. **Detectar qué está roto, falso, desconectado o incompleto**
4. **Corregir lógica, datos, rutas, estados e interacciones**
5. **Recién después rediseñar UI**
6. **Validar que el resultado final sea superior en operación y diseño**

---

# PRINCIPIO RECTOR

**No eliminar por intuición. No rediseñar por impulso. No reemplazar por estética.**
Primero debes entender completamente el sistema actual.

Antes de borrar, rehacer, ocultar o simplificar cualquier módulo, debes hacer una auditoría para responder:

- qué funciona realmente,
- qué no funciona,
- qué funciona parcialmente,
- qué está simulado,
- qué está conectado a fuentes incorrectas,
- qué sí debe conservarse,
- qué debe corregirse,
- y qué debe rediseñarse por completo.

---

# REGLA CRÍTICA: NO ROMPER NADA QUE SÍ FUNCIONA

Cualquier componente, flujo, consulta, ruta, widget, tabla, acción o vista que hoy funcione correctamente debe:

- preservarse,
- documentarse,
- protegerse durante la refactorización,
- y mantenerse operativo después del rediseño.

## Prohibición absoluta
No puedes sacrificar funcionalidad real por estética.
No puedes eliminar módulos útiles solo porque se ven antiguos.
No puedes reemplazar comportamiento operativo real por una UI visualmente atractiva pero vacía.

# FASE 2 — MAPA DE VERDAD DEL SISTEMA

Antes de corregir, debes clasificar cada elemento del dashboard en una de estas categorías:

## Estado A — Real y funcional
Está conectado a datos reales, responde bien y sí sirve operacionalmente.

## Estado B — Real pero defectuoso
Tiene base real pero falla en cálculo, navegación, visualización, filtros o interacción.

## Estado C — Visualmente presente pero no funcional
Existe en pantalla, pero no abre nada, no filtra, no navega o no tiene utilidad real.

## Estado D — Ficticio o engañoso
Usa mocks, hardcodes, demo data, agregaciones inventadas o simulaciones visuales.

## Estado E — Prescindible o mal planteado
No aporta valor operativo, confunde, duplica funciones o da una falsa sensación de capacidad.

Cada componente debe clasificarse antes de decidir si se:
- conserva,
- corrige,
- reconstruye,
- reemplaza,
- o elimina.

# FASE 3 — PROHIBICIONES ABSOLUTAS

No puedes dejar en el resultado final nada de esto:

- mocks en producción
- demo data visible
- seed data usada como si fuera real
- números hardcodeados
- revenue inventado
- bookings inventados
- rankings falsos
- gráficas sintéticas
- tendencias simuladas
- clientes fake
- plataformas fake
- barcos ficticios
- botones sin acción
- cards que aparentan drill-down sin destino real
- ventanas que no cargan nada
- módulos “coming soon” disfrazados de funcionalidad
- placeholders numéricos que parezcan métricas reales
- datos de fallback falsos para “llenar” el dashboard

## Regla de oro
Si no hay datos reales:
- mostrar vacío,
- mostrar “sin datos”,
- mostrar “sin reservas registradas”,
- mostrar “no hay información disponible para este filtro”.

**Nunca inventar para completar la interfaz.**

- futurista

- útil para operar

## El nuevo diseño debe lograr
- jerarquía visual impecable
- excelente uso de espaciado
- KPIs prioritarios arriba
- navegación clara
- estados vacíos bien diseñados
- densidad informativa equilibrada
- excelente contraste
- tablas legibles

- sensación premium sin caer en ruido visual

- saturación de efectos

- complejidad sin valor operativo

## Principio de diseño
La interfaz debe verse como un producto de clase mundial,
pero debe comportarse como una herramienta seria de operación real.

# FASE 8 — REDISEÑO SIN PÉRDIDA DE CAPACIDADES

Antes de sustituir cualquier componente actual, debes verificar si ya cumple una función útil.

## Reglas
- si algo funciona, protégelo

- si algo está mal conectado pero tiene valor, corrígelo
- si algo sobra y no aporta, elimínalo
- si algo aparenta funcionalidad pero no existe, o lo construyes bien o lo quitas

El rediseño debe ser una **evolución superior**, no una demolición irresponsable.
